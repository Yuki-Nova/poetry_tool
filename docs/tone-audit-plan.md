# 平仄表错漏检查与修复计划（古今音双表方案）

> 状态：计划（2026-08-02 制定，已核实数据源结构）
> 问题：① 古今音差异但平仄表只有一张；② 部分字未收录 / 平仄分类错误
> 范围：`tool/src/data/tones.json`（8232 字，平 3000 / 仄 4497 / 多 735）+ 分析引擎

---

## 一、数据源核实结果（已实测）

| 数据源 | 结构 | 平仄分类能力 | 规模 |
|---|---|---|---|
| `tool/src/data/tones.json`（现有） | `{字: 平/仄/多}` | 单表，**有错漏**（已检出冲突） | 8232 字 |
| `chinese_word_rhyme-main/data/Pingshui_Rhyme.json` | 5 声部（上平/下平/上声/去声/入声）→ 各韵部 → 字 | ✅ **上平+下平=平，上去入=仄**（中古音权威） | 8232 字 |
| `chinese_word_rhyme-main/data/Xinyun_Rhyme.json` | 14 部 → {平:[字], 仄:[字]} | ✅ **自带现代普通话平仄** | 6730 字 |
| `chinese_word_rhyme-main/data/Cilin_Rhyme.json` | 19 部 → {平声:[字], 仄声:[字]} | ✅ 中古音（词） | 5037 字 |

**关键结论**：
1. **无需爬新数据**——平水韵（中古）与中华新韵（现代）韵书本身就按平仄分类，可直接推导出两张权威平仄表
2. 现有 tones.json 与平水韵交叉比对，已检出 **153 处直接冲突**（如「喑」tones=仄 但平水韵=平，「填」tones=仄 但平水韵=平）——**证明现有表确实有错**
3. 平水韵 8232 字全部在 tones.json 中（未收录 0），但**新韵 6730 字中必有不在 tones 的现代字**（待统计）——这就是"未收录"的来源

## 二、核心方案：古今音双平仄表

```
中古表（classic）← 平水韵推导 + 词林正韵交叉校验
   适用：选平水韵 / 词林正韵 时使用（传统诗词格律）
现代表（modern） ← 中华新韵推导
   适用：选中华新韵 时使用（普通话读音）

toneAnalyzer：按 effectiveRhymeBook 选择平仄表
   词林正韵/平水韵 → classic
   中华新韵       → modern
   custom.json 覆盖保持最高优先级（用户手动修正）
```

**为什么双表能根治"古今音差异"**：
- 「白」「国」「竹」「一」等：现代普通话读平声（新韵=平），中古为入声（平水韵=仄）——**这不是错误，是两套音系**，单表永远无法两全
- 双表后：写诗选平水韵 → 入声按仄判；写新韵诗 → 按普通话判，各得其所

## 三、检查与修复步骤

### M-A 生成两张权威平仄表（脚本自动化）

```
longyusheng_crawler/tone_audit/
├── build_tables.py     # 推导 classic/modern 两表
│   ├── classic: Pingshui 上平/下平→平，上去入→仄；与 Cilin 交叉（冲突→疑点清单）
│   ├── modern:  Xinyun 平→平，仄→仄
│   └── 多音字：同一字在平水韵同时现于平/仄部 → 标「多」（如「强」「看」）
├── diff_tones.py       # 现有 tones.json vs 两表 → 差异分类
├── check_coverage.py   # 未收录字检查（见 M-C）
└── output/
    ├── tones-classic.json   # 中古平仄表（新文件，前端打包）
    ├── tones-modern.json    # 现代平仄表（新文件）
    ├── tone_diff_report.md  # 错漏报告
    └── tone_coverage_report.md  # 覆盖率报告
```

### M-B 错漏分类与报告（diff_tones.py）

```
对每个字，与两表比对，输出分类报告：
┌─────────────────────────┬────────────────────────────────┐
│ 类别                     │ 含义                          │
├─────────────────────────┼────────────────────────────────┤
│ A 确凿错误（单表矛盾）    │ tones=平 但 平水韵=仄 且 新韵=仄  │
│                         │ （现代/中古都是仄，表里标平）     │
│ B 古今音差异（需双表）    │ tones=仄 但 新韵=平（如入声字）   │
│ C 多音字缺失             │ 平水韵平仄两收，表里只标一个声调   │
│ D 数据冲突（数据源问题）  │ 平水韵与词林正韵不一致           │
│ E 未收录                 │ 新韵/常用字不在 tones.json       │
└─────────────────────────┴────────────────────────────────┘
A 类 → 直接修复 tones.json
B 类 → 双表方案解决（不改单表）
C 类 → 标「多」
D 类 → 记入疑点清单，人工裁决
E 类 → 补录
```

### M-C 未收录字检查（check_coverage.py）

```
检查范围（按优先级）：
  1. 龙榆生 153 词牌全部字位（格律谱中出现的每个字）— 用户实际使用面
  2. 中华新韵 6730 字 − tones.json 已有字 = 现代常用字缺口
  3. 平水韵 8232 字 − tones.json = 中古字缺口
  4. GB2312 一级汉字（3755 常用字）− tones.json = 基础缺口
  5. 可选：龙榆生例词文本（ces JS 变量）中的字
输出：未收录字清单 + 每个字应从哪张表补录（classic/modern/双收）
```

### M-D 人工复核

```
产出 tone_diff_report.md + tone_coverage_report.md 后：
  - A/C/E 类自动修复提案（脚本生成补丁 JSON）
  - B/D 类 + 多音字争议 → 你抽样裁决（按优先级：龙榆生词牌涉及字 > 常用字 > 生僻字）
  - 复核通过 → 应用补丁生成 tones-classic.json / tones-modern.json
```

### M-E 前端接入

```
1. tool/src/data/ 新增 tones-classic.json / tones-modern.json（可由脚本生成后拷贝）
2. core/toneAnalyzer.js：lookupTone(char, rhymeBook) 按韵书选表
   custom.json > 对应表（classic/modern）
3. useAnalysis.js：传递 effectiveRhymeBook 到 analyzeText/analyzeLine
4. 多音字候选（charClassifier）：MULTI_TONE_MAP 增加按音系区分的候选
   （如「白」：中古仄(bó 入) / 现代平(bái)——候选读音随韵书切换）
5. 回归：npm test（33 用例需同步适配双表参数）+ 构建
```
